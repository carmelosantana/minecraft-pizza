# Pizza v0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Timber Blast Axe and a Sweet (gluten-free) Bread to Pizza's Cool Items menu, reusing the existing console-give catalog pattern.

**Architecture:** Data-only change. Two buttons added to the `catalog` menu in `config.yml`, two roots added to `command-allowlist`, `ShippedConfigTest` extended, the config's new SHA-256 appended to `config-hashes.txt` (so an unmodified v0.3.0 config auto-heals on upgrade), and the Maven version bumped. No Java source changes, no new permissions, no new button shapes.

**Tech Stack:** Paper plugin, Java 25, Maven, SnakeYAML, JUnit 5.

## Global Constraints

- `command-allowlist` is fail-closed: every dispatchable command's root MUST be listed, or the button is refused at load and dropped from the menu. Both new roots must be added.
- Editing `src/main/resources/config.yml` changes its SHA-256. The new hash MUST be appended as the last line of `src/main/resources/config-hashes.txt`, keeping all existing lines. `ConfigHashesTest.currentDefaultHashIsListed` fails CI otherwise.
- Config auto-refresh must remain non-destructive: existing hash lines are never removed (they are the "known older defaults" that trigger auto-heal).
- No `org.geysermc.*` imports outside `FloodgateBridge`/`BedrockRenderer` (untouched here).
- Version: `pom.xml` project version becomes `0.4.0`.
- This must all land in ONE task: because editing `config.yml` invalidates the current-default hash, splitting the config edit from the hash append would leave `ConfigHashesTest` red between tasks.

### Task 1: Add Timber Blast + Sweet Bread to the catalog

**Files:**
- Modify: `src/main/resources/config.yml` (catalog buttons + allowlist roots)
- Modify: `src/main/resources/config-hashes.txt` (append new current-default hash)
- Modify: `src/test/java/org/xpfarm/pizza/config/ShippedConfigTest.java` (extend two existing assertions)
- Modify: `pom.xml` (version `0.3.0` → `0.4.0`)

**Interfaces:**
- Consumes: existing `ConfigParser.parse`, `PizzaConfig.menus()/commandAllowlist()`, `Action.RunCommand.command()` (all unchanged).
- Produces: no new code interfaces; the shipped `config.yml` gains two `catalog` buttons dispatching `timberblast give %player%` and `gfbread give sweet %player% 3`, and two allowlist roots `timberblast`, `gfbread` (the allowlist matches a command's first token, so the bread root is the command name `gfbread`, not the artifact name `glutenfreebread`).

- [ ] **Step 1: Extend the failing test**

In `src/test/java/org/xpfarm/pizza/config/ShippedConfigTest.java`, add two assertions to the end of `newCatalogButtonsAreAcceptedAndDispatchTheirCommands()` (after the `llama` assertion):

```java
        assertTrue(commands.contains("timberblast give %player%"));
        assertTrue(commands.contains("gfbread give sweet %player% 3"));
```

And extend `newRootsAreInTheAllowlist()` to also require the two new roots:

```java
        assertTrue(allow.containsAll(List.of("aguadeflorida", "electricfurnace", "llama")));
        assertTrue(allow.containsAll(List.of("timberblast", "gfbread")));
```

- [ ] **Step 2: Run the test to verify it fails**

```bash
export PATH="$HOME/.sdkman/candidates/maven/current/bin:$HOME/.sdkman/candidates/java/current/bin:$PATH"
mvn -q -Dtest=ShippedConfigTest test
```

Expected: FAIL — `newCatalogButtonsAreAcceptedAndDispatchTheirCommands` and `newRootsAreInTheAllowlist` fail because the catalog has neither command yet and the allowlist lacks both roots.

- [ ] **Step 3: Add the two catalog buttons**

In `src/main/resources/config.yml`, in `menus.catalog.buttons`, append after the `Llama Companion` button (keep the existing 4-space list indentation):

```yaml
      - label: Timber Blast Axe
        run-as: console
        command: timberblast give %player%
        cooldown: 24h
      - label: Sweet Bread
        run-as: console
        command: gfbread give sweet %player% 3
        cooldown: 15m
```

- [ ] **Step 4: Add the two allowlist roots**

In `src/main/resources/config.yml`, in `command-allowlist`, append after `- curse`:

```yaml
  - timberblast
  - gfbread
```

- [ ] **Step 5: Run ShippedConfigTest to verify it passes**

```bash
mvn -q -Dtest=ShippedConfigTest test
```

Expected: PASS — all five `ShippedConfigTest` methods green (including `shippedConfigParsesWithoutWarnings`, since both roots are now allowlisted so no button is refused).

- [ ] **Step 6: Append the new config hash**

The config edit invalidated the current-default hash, so `ConfigHashesTest` is now red. Recompute and append (do NOT remove the existing three lines):

```bash
sha256sum src/main/resources/config.yml | cut -d' ' -f1 >> src/main/resources/config-hashes.txt
cat src/main/resources/config-hashes.txt
```

Expected: `config-hashes.txt` now has four lines; the fourth is the new hash of the edited `config.yml`.

- [ ] **Step 7: Bump the version**

In `pom.xml`, change the project version (the first `<version>` element, the one directly under `<artifactId>pizza</artifactId>`):

```xml
    <version>0.4.0</version>
```

- [ ] **Step 8: Run the full verify**

```bash
mvn -q clean verify
```

Expected: PASS — full suite green, including `ConfigHashesTest.currentDefaultHashIsListed` (new hash present) and `ConfigHashesTest.currentDefaultBytesAreTheBundledConfig`.

- [ ] **Step 9: Commit**

```bash
git add src/main/resources/config.yml src/main/resources/config-hashes.txt \
        src/test/java/org/xpfarm/pizza/config/ShippedConfigTest.java pom.xml
git commit -m "feat: add Timber Blast Axe and Sweet Bread to the Cool Items menu (v0.4.0)"
```
