# Pizza v0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Copper Sword and a Shop button to the menu, and give every Java chest button a real item icon instead of paper.

**Architecture:** Task 1 is a small, backward-compatible Java change — `ButtonImage` gains an optional `material` field that the Java `ChestRenderer` uses for its icon and the Bedrock renderer ignores, with the icon-name resolution extracted to a pure static for testing. Task 2 is config: the two new buttons, an `image.material` on every shipped button, two allowlist roots, the config-hash bump, the version bump, and test coverage. Task 1 leaves the tree green with no behaviour change to existing configs (no `material` key present yet); Task 2 wires the icons and new buttons in.

**Tech Stack:** Paper plugin, Java 25, Maven, SnakeYAML, JUnit 5.

## Global Constraints

- `ConfigParser` and the `menu`/`config` model stay Bukkit-free: `ButtonImage.material` is a plain `String` (a Material *name*), never a `org.bukkit.Material`. Only `ChestRenderer` (already Bukkit-facing) resolves the name to a `Material`.
- `BedrockRenderer` must not read `image.material()`; it reads only `type`/`data`. The new field must produce no Bedrock icon and no broken Bedrock texture path.
- `command-allowlist` is fail-closed: a command's first-token root MUST be listed. New roots: `copperkingdom` (for `copperkingdom give copper_sword`) and `market` (for `market`).
- Editing `config.yml` changes its SHA-256; append the new hash as the last line of `config-hashes.txt`, keeping all existing lines (they drive non-destructive auto-heal). `ConfigHashesTest.currentDefaultHashIsListed` guards it.
- Version: `pom.xml` project version becomes `0.5.0`.
- A bad/unrecognised icon is cosmetic: it logs a warning and falls back to `Material.PAPER`, never throwing — existing `ChestRenderer` philosophy, preserved.

/**
 * An image reference attached to a button. {@code type} names the source (e.g. an item texture or

    private static ButtonImage parseImage(Object raw) {
        Map<String, Object> map = asMap(raw);
        if (map == null) {
            return null;
        }
        String type = asString(map.get("type"), null);
        String data = asString(map.get("data"), null);
        String material = asString(map.get("material"), null);
        if (type == null && data == null && material == null) {
            return null;
        }
        return new ButtonImage(type, data, material);
    }

- [ ] **Step 5: Resolve the icon name in `ChestRenderer`**

In `src/main/java/org/xpfarm/pizza/render/ChestRenderer.java`, replace `materialFor` (currently at 193-205) with a delegating instance method plus a pure static. Keep the existing imports (`Material`, `Locale`, `ButtonImage` are already imported):

```java
    private Material materialFor(Button button) {
        String name = iconNameFor(button.image());
        if (name == null) {
            return Material.PAPER;
        }
        try {
            return Material.valueOf(name.toUpperCase(Locale.ROOT));
        } catch (IllegalArgumentException e) {
            plugin.getLogger()
                    .warning("button " + button.id() + " has an unrecognised material '"
                            + name + "'; using a default icon");
            return Material.PAPER;
        }
    }

    /**
     * The Bukkit {@link Material} name to use as a button's Java chest icon, or {@code null} to fall
     * back to {@link Material#PAPER}. Prefers the dedicated {@link ButtonImage#material()} field,
     * then the legacy {@code type: material} image whose payload is the name; a Bedrock-only
     * {@code type: path} image (or no image) yields {@code null}. Pure and Bukkit-free so it is unit
     * testable without a running server — only {@link #materialFor} touches {@link Material}.
     */
    static String iconNameFor(ButtonImage image) {
        if (image == null) {
            return null;
        }
        if (image.material() != null && !image.material().isBlank()) {
            return image.material();
        }
        if ("material".equalsIgnoreCase(image.type()) && image.data() != null) {
            return image.data();
        }
        return null;
    }
```
