# Pizza v0.5.1 — Copper Sword to plain console dispatch

Date: 2026-07-28
Status: approved
Branch: `feat/pizza-v0.5.1`

## Summary

Copper Kingdom v0.3.0 (released + enrolled) now supports `copperkingdom give <item> <player>` from
console with Floodgate-aware target resolution. Retire the v0.5.0 `player-elevated` workaround on the
Copper Sword button and switch it to plain `run-as: console` like every other catalog item. Config-only.

## Change

`menus.catalog` Copper Sword button, from:

```yaml
- label: Copper Sword
  image: { material: COPPER_INGOT }
  run-as: player-elevated
  grant: [copperkingdom.give]
  command: copperkingdom give copper_sword
```

to:

```yaml
- label: Copper Sword
  image: { material: COPPER_INGOT }
  run-as: console
  command: copperkingdom give copper_sword %player%
```

- Drops the one-shot `copperkingdom.give` grant and the elevated run mode.
- Adds the `%player%` placeholder — console must name the recipient; Copper Kingdom v0.3.0 resolves it
  (Floodgate-aware). The icon (`COPPER_INGOT`) and allowlist root (`copperkingdom`) are unchanged.

## Deploy ordering (the one caveat)

This dispatch only works once the running server has pulled **Copper Kingdom v0.3.0**. Both plugins
are enrolled, so a server recreation pulls both latest together — the switch is consistent on the next
recreation. (User accepted this ordering when choosing to ship now.)

## Mechanics

- `config.yml` edited ⇒ append its new SHA-256 to `config-hashes.txt` (existing lines untouched).
- `pom.xml` version → `0.5.1`.
- `ShippedConfigTest` catalog assertion updated from `copperkingdom give copper_sword` to
  `copperkingdom give copper_sword %player%`.
- Full `mvn clean verify` green; gate 7a confirms enable + `copperkingdom` root still validates.

## Non-goals

No other button changes; the Java icons and Shop button from v0.5.0 are unaffected.
